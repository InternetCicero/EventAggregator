# Spec: „Für dich“: persönliche Event-Empfehlungen (und Unternavigation)

- **Status:** In Review
- **Version:** 1.1
- **Autor:** Laurenz Polanski (mit Claude)
- **Erstellt:** 2026-11-07
- **Approved:** 2026-11-07

## 1. Ziel

Nutzer legen ein kleines Interessenprofil an und bekommen in der Event-Übersicht einen Reiter **„Für dich“**: kommende Events, nach Passung sortiert und mit Begründung („Kategorie Consulting · „case“ im Titel · in München“).

Leitplanken:

- **Das Profil verlässt den Browser nie.** Es liegt nur im `localStorage`, gerechnet wird im Browser, an den Server gehen keine Profildaten. Der Server bekommt dieselbe Anfrage wie die normale Event-Liste. Damit verarbeitet der Betreiber keine Profildaten.
- **Ohne KI, ohne Konten.** Regelbasierte, erklärbare Punktwertung.
- **Das Profil ist die einzige Schnittstelle.** Spätere Eingabewege (CV-Vorschlag, eigene KI) befüllen nur das Profil. Die Rechnung bleibt unverändert.

Zusätzlich wird die Navigation aufgeräumt: „Event hinzufügen“ wandert unter **Events**, „Stelle einreichen“ unter **Jobs & Praktika**.

## 2. Scope

**Teil A: Unternavigation**
- Hauptnavigation nur noch: Events · Jobs & Praktika · Materialien · Admin
- Events-Bereich bekommt eine Reiterleiste: **Alle Events** (`/`) · **Für dich** (`/fuer-dich`) · **Event hinzufügen** (`/einreichen`)
- Jobs-Bereich bekommt eine Reiterleiste: **Alle Stellen** (`/jobs`) · **Stelle einreichen** (`/jobs/einreichen`)
- Die bestehenden URLs bleiben unverändert, damit Lesezeichen und Links weiter funktionieren
- Der Hauptpunkt ist auf allen Unterseiten seines Bereichs aktiv markiert (z. B. „Events“ auf `/einreichen`)

**Teil B: „Für dich“**
- Profil-Editor (anlegen, bearbeiten, löschen)
- Ranking-Funktion `rank()` als reines JS-Modul mit Unit-Tests
- Ergebnisansicht in zwei Gruppen mit Begründungen pro Event
- Ergänzung der Datenschutzerklärung

## 3. Non-Goals

- Keine Empfehlungen für Jobs (folgt später mit eigenen Teilbewertungen auf derselben Rechnung)
- Kein CV-Upload, kein LinkedIn-Import, keine Lückenanalyse, keine Karriereziele
- Keine Konten, keine Speicherung von Profilen auf dem Server, kein Sync zwischen Geräten
- Kein „Nicht interessiert“-Knopf pro Event (mögliche Erweiterung)
- Keine Anzeige von Prozentwerten (wirkt präziser, als es ist), nur Gruppe und Gründe
- Keine Änderung an Server-API oder Datenbank

## 4. Annahmen

- A1 `GET /api/events` ohne Parameter liefert alle laufenden und kommenden freigegebenen Events (heute rund 50 bis 160). Die Rechnung im Browser ist dafür schnell genug, eine Paginierung gibt es nicht.
- A2 Gewichte, Schwellen und Ausschlussregeln wie im Chat abgestimmt (Abschnitt 6.3). Ausgeschlossene Kategorien blenden Events aus.
- A3 Die Besucherstatistik zählt `/fuer-dich` wie jede andere Seite, nur den Pfad. Das Profil wird dabei nicht übertragen.
- A4 Das Speichern des Profils im Browser ist für eine vom Nutzer ausdrücklich gewünschte Funktion unbedingt erforderlich (§ 25 Abs. 2 Nr. 2 TDDDG), daher ist keine Einwilligung nötig. Das wird in der Datenschutzerklärung beschrieben. Keine Rechtsberatung, bei Unsicherheit kurz prüfen lassen.

## 5. Akzeptanzkriterien

**Navigation**
- **AC-1** WHEN eine Seite angezeigt wird, THE SYSTEM SHALL in der Hauptnavigation genau „Events“, „Jobs & Praktika“, „Materialien“ und „Admin“ zeigen.
- **AC-2** WHEN `/`, `/fuer-dich` oder `/einreichen` angezeigt wird, THE SYSTEM SHALL „Events“ in der Hauptnavigation als aktiv markieren und die Reiterleiste „Alle Events · Für dich · Event hinzufügen“ mit dem passenden aktiven Reiter zeigen.
- **AC-3** WHEN `/jobs`, `/jobs/einreichen` oder `/jobs/:id` angezeigt wird, THE SYSTEM SHALL „Jobs & Praktika“ als aktiv markieren. Auf `/jobs` und `/jobs/einreichen` erscheint die Reiterleiste „Alle Stellen · Stelle einreichen“.
- **AC-4** WHEN die Seite 375 px breit ist, THE SYSTEM SHALL Haupt- und Reiterleiste ohne horizontalen Seitenüberlauf darstellen (bestehender UI-Test plus neue Seiten).

**Profil**
- **AC-5** WHEN ein Nutzer das Profil speichert, THE SYSTEM SHALL es unter dem Schlüssel `studenthub.profile` mit `version: 1` im `localStorage` ablegen und nach dem Neuladen wiederherstellen.
- **AC-6** WHEN der gespeicherte Wert fehlt, kein gültiges JSON ist, eine unbekannte Version hat oder der Speicher nicht zugreifbar ist (z. B. privater Modus), THE SYSTEM SHALL ohne Fehler mit einem leeren Profil starten.
- **AC-7** WHEN ein Profil gespeichert wird, THE SYSTEM SHALL unbekannte Kategorien verwerfen, Schlagwörter auf höchstens 15 Einträge mit je höchstens 40 Zeichen und Städte auf 60 Zeichen begrenzen sowie Duplikate entfernen.
- **AC-8** WHEN eine Kategorie gleichzeitig als „interessiert mich“ und „interessiert mich nicht“ gewählt würde, THE SYSTEM SHALL nur die zuletzt gewählte Zuordnung behalten.
- **AC-9** WHEN der Nutzer „Profil löschen“ bestätigt, THE SYSTEM SHALL den Schlüssel entfernen und den Einstieg ohne Profil zeigen.

**Datenschutz**
- **AC-10** WHEN der Reiter „Für dich“ genutzt wird (Profil anlegen, ändern, Ergebnisse ansehen, löschen), THE SYSTEM SHALL keinen Profilinhalt in URL, Query-Parametern, Request-Bodies oder Headern an den Server senden (Nachweis per UI-Test mit eindeutigem Test-Schlagwort).
- **AC-11** WHEN `/datenschutz` angezeigt wird, THE SYSTEM SHALL einen Abschnitt zum Profil „Für dich“ enthalten (nur im Browser, keine Übertragung, Löschen per Knopf oder über die Browserdaten).

**Ranking (`rank(events, profile, { today })`)**
- **AC-12** WHEN das Profil weder Kategorien noch Schlagwörter noch eine Hauptstadt enthält, THE SYSTEM SHALL kein Ranking zeigen, sondern den Einstieg mit Profil-Editor.
- **AC-13** WHEN ein Event eine ausgeschlossene Kategorie hat, bereits beendet ist oder später als `horizonDays` nach heute beginnt, THE SYSTEM SHALL es nicht bewerten und nicht anzeigen.
- **AC-14** WHEN Teilbewertungen berechnet werden, THE SYSTEM SHALL nur die anwendbaren (zugehöriges Profilfeld gesetzt) in Zähler und Nenner einbeziehen: Score = Σ Punkte / Σ maximale Punkte × 100.
- **AC-15** WHEN ein Schlagwort nur als Teil eines Wortes vorkommt (z. B. „EY“ in „Keynote“), THE SYSTEM SHALL das nicht als Treffer werten. Groß-/Kleinschreibung und Umlaute (ä/ae usw.) werden ignoriert.
- **AC-16** WHEN Events gleich viele Punkte haben, THE SYSTEM SHALL das frühere Event zuerst zeigen, danach das mit der kleineren ID.
- **AC-17** WHEN mehrere Events derselben Quelle oben stehen, THE SYSTEM SHALL die Reihenfolge so berechnen, dass jedes Event mit `score × 0,9^n` zählt, wobei n die Zahl bereits einsortierter Events derselben Quelle ist (gierige Auswahl).
- **AC-18** WHEN gerankt wurde, THE SYSTEM SHALL Events mit Score ≥ 60 unter „Passt sehr gut“ und 30 bis 59 unter „Könnte dich interessieren“ zeigen. Darunter erscheint ein Hinweis mit der Anzahl weiterer Events und einem Link zu „Alle Events“.
- **AC-19** WHEN ein Event angezeigt wird, THE SYSTEM SHALL die Gründe aller Teilbewertungen mit Punkten > 0 in fester Reihenfolge (Kategorie, Schlagwort, Ort, Format, Zeitnähe) anzeigen, höchstens 3.
- **AC-20** WHEN das Rechenbeispiel aus 6.3 als Testfall gerechnet wird, THE SYSTEM SHALL 99 (gerundet) für den Case-Workshop und 21 für das Online-Networking liefern.

**Nicht-Regression**
- **AC-21** WHEN die Änderung ausgerollt ist, THE SYSTEM SHALL alle bestehenden Server-, Client- und UI-Tests grün halten. Die Seiten `/`, `/einreichen`, `/jobs`, `/jobs/einreichen` behalten ihre URLs.

## 6. Design

### 6.1 Navigation

- `client/src/App.jsx`: Hauptnavigation ohne „Event hinzufügen“ und „Stelle einreichen“. Aktiv-Logik pro Bereich über eine kleine Funktion `sectionOf(pathname)` (`events` für `/`, `/fuer-dich`, `/einreichen`; `jobs` für `/jobs*`) statt `end`-Matching.
- Neue Komponente `client/src/components/SectionTabs.jsx` (Liste von `{ to, label }`, rendert `NavLink`s im bestehenden Stil der Segment-Umschalter). Eingebunden in `EventList`, `ForYou`, `SubmitEvent` bzw. `JobList`, `SubmitJob`.
- Neue Route `/fuer-dich` → `client/src/pages/ForYou.jsx`.

### 6.2 Profil

```js
// client/src/lib/matching/profile.js
{
  version: 1,
  categories: [],          // Kategorien aus /api/events/categories
  excludedCategories: [],
  keywords: [],            // frei, Vorschläge aus /api/events/tags
  cities: { primary: '', secondary: '' },
  acceptOnline: true,
  formats: [],             // 'online' | 'onsite' | 'hybrid'; leer = egal
  horizonDays: 60,         // 30 | 60 | 90
  updatedAt: 'YYYY-MM-DD'
}
```

Funktionen: `emptyProfile()`, `sanitizeProfile(raw, { categories })` (AC-7, AC-8), `loadProfile(storage)` / `saveProfile(storage, p)` / `clearProfile(storage)` mit try/catch (AC-5, AC-6, AC-9), `isActive(p)` (AC-12). `storage` wird übergeben, damit die Tests ohne Browser laufen.

Editor `client/src/components/ProfileEditor.jsx`:
- Kategorien als Chips mit drei Zuständen: neutral → „interessiert mich“ → „nicht interessiert“ → neutral
- Schlagwörter als Eingabe mit Chips, Vorschläge aus der Tag-Liste (`datalist`)
- Hauptstadt, Zweitstadt (Text), „Online-Events sind für mich okay“ (Checkbox, Standard an)
- Format: Mehrfachauswahl, leer = egal
- Zeitraum: Umschalter 30 / 60 / 90 Tage
- Speichern, Profil löschen (mit Bestätigung), Hinweis „Dein Profil bleibt auf diesem Gerät“

### 6.3 Ranking

Module unter `client/src/lib/matching/`:

| Datei | Inhalt |
|---|---|
| `normalize.js` | `fold(text)`: Kleinschreibung, ä→ae, ö→oe, ü→ue, ß→ss, Satzzeichen → Leerzeichen; `containsPhrase(haystack, needle)` mit Wortgrenzen; `matchesCity(location, city)` mit kleiner Alias-Liste (München/Munich, Köln/Cologne, Wien/Vienna, Zürich/Zurich) |
| `weights.js` | Gewichte und Schwellen (unten) |
| `eventScorers.js` | fünf Teilbewertungen, jeweils `(event, profile, ctx) → null \| { points, max, reason }` |
| `rank.js` | allgemeine Rechnung `rank(items, profile, { scorers, exclusions, today })` |

**Teilbewertungen**

| Name | max | Anwendbar wenn | Punkte |
|---|---|---|---|
| Kategorie | 40 | `categories` nicht leer | 40, wenn `event.category` enthalten |
| Schlagwort | 25 | `keywords` nicht leer | 25 × min(1, Σ Trefferstärke); Treffer in Tag oder Titel = 1, nur Beschreibung = 0,6 |
| Ort | 20 | Haupt- oder Zweitstadt gesetzt | Hauptstadt 1,0 · Zweitstadt 0,7 · Online/Hybrid bei `acceptOnline` 0,8; bei Hybrid zählt der höhere Wert |
| Format | 10 | `formats` nicht leer | 10 bei Treffer, 5 bei unbekanntem Format |
| Zeitnähe | 5 | immer, aber nur wenn das Profil aktiv ist (AC-12) | 5 × (1 − Tage bis Start / `horizonDays`), laufende Events = 5 |

**Ausschlussregeln (vor der Bewertung):** ausgeschlossene Kategorie; `end_date` (oder `start_date`) vor heute; Start später als `today + horizonDays`.

**Schwellen:** ≥ 60 „Passt sehr gut“, 30–59 „Könnte dich interessieren“. Der Vielfaltsabzug (AC-17) beeinflusst nur die Reihenfolge, nicht die Gruppe.

**Rechenbeispiel (AC-20).** Profil: Kategorien „Consulting“, „Workshop & Case Study“; Schlagwort „case“; Hauptstadt München; Online okay; `horizonDays` 60.
- „Case-Workshop Strategy“, Workshop & Case Study, vor Ort, München, in 10 Tagen: 40 + 25 + 20 + 4,17 = 89,17 von 90 → **99**
- „Online-Networking Banking“, Networking, online, in 30 Tagen: 0 + 0 + 16 + 2,5 = 18,5 von 90 → **21**

### 6.4 Ansicht

`ForYou.jsx`: lädt Kategorien, Tags und `api.getEvents({})` (dieselbe Anfrage wie „Alle Events“, keine Profilparameter). Ohne aktives Profil: Einstieg mit Erklärung und Editor. Mit Profil: eingeklappter „Profil bearbeiten“-Bereich, darunter die zwei Gruppen.

`EventCard` bekommt ein optionales Prop `reasons` (Zeile „Warum: …“ unter den Metadaten). Ohne Prop bleibt die Karte unverändert.

### 6.5 Datenschutz

Neuer Abschnitt in `Datenschutz.jsx`: „Persönliches Profil (Für dich)“. Er beschreibt, was gespeichert wird, dass es nur im Browser liegt und nicht übertragen wird, die Rechtsgrundlage (A4) und das Löschen. Der Satz im Statistik-Abschnitt („Da keine Informationen auf Ihrem Gerät gespeichert …“) wird so präzisiert, dass er sich nur auf die Statistik bezieht.

## 9. Risiken

- **Dünne Profile, schwache Treffer:** Durch die Normalisierung bekommen kleine Profile faire Scores. Der Einstieg erklärt, dass mehr Angaben bessere Empfehlungen ergeben.
- **Kategorien der Scraper ungenau:** Die Schlagwörter fangen das teilweise ab. Die Qualität der Empfehlungen hängt an der Kategorisierung beim Scraping.
- **Ortsangaben im Freitext:** Die Alias-Liste deckt die häufigsten Fälle ab, Fehltreffer sind möglich. Darum hat der Ort nur 20 Punkte.
- **Profil nur auf einem Gerät:** Gewollt (keine Konten). Ein Export/Import als Datei wäre eine einfache Erweiterung.
